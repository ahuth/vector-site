Why Vector

When code is cheap, judgment is what’s scarce.

Agents can produce a pull request in minutes. They can’t tell you whether it should exist, whether the abstraction will hold up next year, or which shortcut is going to cost you.

That was always the hard part of engineering. Now it’s most of the job. Vector is built for working at that level: engineering without spending your day in the diff.

  1. What’s worth building?
  2. Where do the boundaries go?
  3. Which tradeoffs can we live with?
  4. Is this actually done?
How it works

An IDE where you work with agents, not files.

A multi-agent development environment. (a MADE, if you like acronyms)

01 · Direct

Start from intent

Organize projects into workspaces. Open a conversation with Claude or Codex about the outcome you want and the constraints that matter.

02 · Delegate

Let agents hand off

Agents delegate to other agents, across providers and models. All of the live activity is in one place instead of scattered across terminals.

03 · Decide

Make the calls

You have context the agents don’t. Ask questions, weigh the alternatives, redirect early, and own the architecture without reading every line.

The beta

Early, on purpose.

Vector is a beta. It’s useful today, and it’s still finding its shape. I’m looking for engineers who want to work this way and will say what works and what doesn’t.
